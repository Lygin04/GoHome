# Настройка Rider

Если `dotnet build` из терминала проходит, а Rider на том же коде падает с `MSB4236` —
сломан не проект, а настройка IDE. Ниже что именно и почему.

Названия пунктов сверены с документацией JetBrains для Rider 2026.2. В других версиях они
могли поменяться — сверяйтесь со своей.

---

## Ошибка первая: MSB4236

```
error MSB4236: SDK "Microsoft.NET.Sdk" не найден.
```

MSBuild не смог разрешить SDK проекта. Практически всегда это значит, что MSBuild и .NET CLI
взяты из разных мест.

Типичная машина выглядит так:

| Где | Что там лежит |
|---|---|
| `%USERPROFILE%\.dotnet` | **SDK** (`sdk\10.0.103`) — сюда ставит скрипт `dotnet-install` |
| `C:\Program Files\dotnet` | только рантаймы (`shared\Microsoft.NETCore.App`), папки `sdk` нет |

Терминал собирает нормально, потому что в `PATH` первым идёт `%USERPROFILE%\.dotnet`.
Rider по умолчанию берёт «канонический» дистрибутив из `Program Files`, не находит там
ни одного SDK — и падает. Добавляет путаницы бандловый MSBuild: Rider приносит свой
(`…\Rider\tools\MSBuild\Current\Bin\amd64\MSBuild.exe`), и он не обязан соответствовать
установленному в системе SDK.

Проверить, что происходит на самом деле:

```powershell
where.exe dotnet     # все найденные хосты по порядку — выигрывает первый
dotnet --list-sdks   # какие SDK видит выигравший
```

Если `dotnet --list-sdks` печатает нужную версию, а Rider ругается — случай ровно этот.

### Со стороны репозитория уже сделано

В корне лежит `global.json` с явной версией SDK и политикой отката:

```json
{
  "sdk": {
    "version": "10.0.103",
    "rollForward": "latestFeature"
  }
}
```

Он убирает неопределённость «какой из установленных SDK возьмётся» и совпадает с версией,
зафиксированной в CI. Но `global.json` выбирает версию **внутри** дистрибутива — заставить
Rider смотреть на другой дистрибутив он не может. Это только настройки IDE.

### Шаг 1. Указать нужный тулсет

`Ctrl+Alt+S` → страница **Build, Execution, Deployment | Toolset and Build**.

**`.NET CLI executable path`** — путь к `dotnet.exe`. Rider определяет его автоматически,
но можно задать свой. Пропишите тот хост, у которого есть SDK:

```
C:\Users\<имя>\.dotnet\dotnet.exe
```

Путь нужен развёрнутый: `%USERPROFILE%` в этом поле не подставляется.

**`MSBuild version`** — список найденных MSBuild плюс возможность указать свой исполняемый
файл в нестандартном месте. Выберите тот, что идёт с .NET SDK, а не бандловый Rider'овский.
Если нужного в списке нет — Rider всё ещё смотрит не на тот дистрибутив, вернитесь к
предыдущему пункту.

**`Automatically download .NET SDK if necessary`** — если галочка стоит, Rider может докачать
SDK сам. Удобно, но так на диске появляется третья копия .NET. Когда нужный SDK уже стоит,
галочку лучше снять: иначе потом не понять, какая копия используется.

### Шаг 2. Перезагрузить решение

Тулсет читается один раз при загрузке решения. После смены настроек закройте решение
и откройте заново — иначе собираться будет по-старому.

### Шаг 3. Если не помогло — почистить кэши

**File | Invalidate Caches…**, кнопка **Invalidate and Restart**.

Модель проекта кэшируется отдельно от настроек, и после смены тулсета в кэше остаются ссылки
на старые пути. Это дорого — после перезапуска решение индексируется целиком, — поэтому шаг
третий, а не первый.

## Ошибка вторая: решение не найдено, в дереве лишний проект

Симптом: Rider не находит файл решения, показывает содержимое папки как есть,
а `src/GoHome/Program.cs` подсвечивает отдельным проектом.

С первой ошибкой она не связана: чинится другим и независимо.

Причины две, обе не в коде:

1. **Rider ищет решение по имени открытой папки.** Не найдя его, он открывает каталог
   в folder mode, а в .NET 10 одиночный `.cs` с точкой входа сам по себе является
   запускаемой программой (file-based apps) — вот `Program.cs` и превращается в проект.
   Решение теперь называется `GoHome.sln` и лежит в корне рядом с папкой `src`.
   Открывать нужно именно его, а не каталог.

2. **Осталось состояние от удалённого проекта.** В `.idea\.idea.GoHome\.idea\workspace.xml`
   прописан `GoHome/GoHome.csproj` — путь от старой раскладки, когда проект лежал в корне.
   Отсюда фантомная конфигурация запуска. Каталог `.idea` целиком в `.gitignore`, это
   локальное состояние IDE: закройте Rider, удалите его, откройте `GoHome.sln` заново.

   ```powershell
   Remove-Item .idea -Recurse -Force
   ```

Имя решения совпадает с именем каталога репозитория намеренно — по нему Rider и ищет.
Одно имя проходит через всё: `GoHome.sln`, `src\GoHome\GoHome.csproj`, сборка `GoHome.exe`,
namespace `GoHome`, задача в планировщике и каталог данных `%APPDATA%\GoHome`.

## Контрольная проверка

Всё описанное выше — про IDE. Проект собирается и без неё, и проверить это стоит **до**
того, как лезть в настройки:

```powershell
dotnet build
dotnet test
```

Проходит из терминала, но падает в Rider — правьте настройки IDE и не трогайте `csproj`.
